# 피규어 3D 뷰어 (가우시안 스플랫)

아이폰으로 피규어 둘레를 한 바퀴 돌며 찍은 동영상(19.6초)으로 3D 알갱이(가우시안 스플랫)를 만들고, 웹에서 돌려 볼 수 있게 했습니다.

- 공개 주소: https://gsahn26.github.io/my-open-space/
- 저장소 주소: https://github.com/gsahn26/my-open-space
- 장면 파일 직접 확인: https://gsahn26.github.io/my-open-space/scene.sog

## 1. 공개 판단

**내 방 바닥에 놓은 피규어만 가까이 찍었고, 사람 얼굴·문패·모니터 화면·주소 같은 개인정보가 화면에 없으므로 남에게 보내도 되는 공간이라고 판단했습니다.** 또 복원할 때 피규어만 오려 내서, 영상 뒤쪽에 비친 방 모습은 결과 파일에 들어가지 않습니다.

## 2. 촬영

| 항목 | 값 |
|---|---|
| 대상 | 나무 바닥 위 피규어 |
| 촬영 방식 | **동영상 1개**, 피규어 둘레를 걸어서 한 바퀴 (IMG_6693.MOV) |
| 영상 | 가로 1920 × 1080, 30fps, 19.6초 (스킬 조건: 가로, 15~20초 충족) |
| 사진 뽑기 | 초당 10장으로 뽑은 196장을 24구간으로 나누고, 구간마다 **가장 선명한 1장**을 골라 24장 (흐린 장면이 섞여 있어서) |
| 사용 프레임 | 24장 중 **20장이 정렬(카메라 위치 추정)에 성공**. 16~19번 4장은 실패 |

## 3. 복원 방법

교안(room-3d 스킬)은 코랩 T4에서 MapAnything을 씁니다. 이번에는 코랩 계정 인증과 모델 내려받기를 할 수 없는 환경이라, GPU 없이 CPU에서 아래 방법으로 만들었습니다. 사진 뽑기(24장), 알갱이 만들기, 줄이기, 띄우기는 스킬과 같은 방법입니다.

1. 장면마다 피규어만 오려 내는 마스크를 만듦 (rembg). 나무 바닥 무늬가 엉뚱한 짝을 만들어서 바닥은 뺐습니다.
2. 피규어 부분만 잘라 DISK 특징점 + LightGlue로 짝을 찾음 (앞뒤 6장씩, 144쌍) → COLMAP으로 카메라 위치 추정 (20장 정렬, 점 6,972개, 재투영 오차 1.31px)
3. 정렬된 20장으로 평면 스윕 스테레오를 해서 장면마다 깊이를 구함 (NCC 0.6 이상만)
4. **다른 장면 2장 이상과 깊이가 1% 안으로 맞는 점만** 남김 → 1,115,009개
5. 각 축 0.5~99.5 백분위 밖, 이웃과 멀리 떨어진 점 제거 → **1,031,047개**
6. 점을 알갱이로 바꿈. 칸 17개(각도별 색 `f_rest` 없음), y·z 부호 뒤집기
7. `splat-transform@3.10.3`으로 `.sog`(SOG v2) 변환

## 4. 측정값

| 항목 | 값 |
|---|---|
| 알갱이 수 | 1,031,047 |
| 카메라 퍼짐 비 | 3.53 (카메라 상자 대각선 11.951 ÷ 장면 상자 대각선 3.389), 기준 0.1보다 큼 |
| 장면의 가장 긴 변 | 2.143 (SfM 단위, 실제 cm 아님) |
| 알갱이 반지름 | K = 1.4 → r = 1.4 × 2.143 ÷ √1,031,047 = 0.00296 |

퍼짐 비가 1보다 훨씬 큰 것은 작은 피규어 둘레를 크게 한 바퀴 돌며 찍었기 때문입니다. 추정된 카메라 20곳이 피규어를 둘러싼 고리 모양으로 나와, 실제로 걸어 돈 경로와 맞는 것을 확인했습니다.

### 형식별 비교 (splat-transform 3.10.3)

크기는 바이트 단위입니다. (1MB = 1,000,000바이트로 보면 `.sog`는 5.68MB, 1MiB = 1,048,576바이트로 보면 5.41MiB)

| 형식 | 파일 크기 (바이트) | 변환 시간 | 알갱이 수 | 알갱이당 바이트 |
|---|---:|---:|---:|---:|
| 원본 `.ply` | 70,111,613 | – | 1,031,047 | 68.0 |
| `.compressed.ply` | 16,787,429 | 3.89초 | 1,031,047 | 16.3 |
| `.spz` | 7,312,021 | 2.83초 | 1,031,047 | 7.1 |
| **`.sog` (사용)** | **5,675,368** | 4.30초 | 1,031,047 | **5.5** |

알갱이당 바이트 = 파일 크기 ÷ 알갱이 수. 원본 `.ply`가 정확히 68바이트라 헤더가 맞게 만들어졌습니다. 네 형식 모두 알갱이 수가 같고, SOG가 원본보다 약 12.4배 작아서 웹에 올릴 파일로 골랐습니다. (원본 `.ply` 70MB는 깃허브 한계 100MiB 아래지만 웹에서 받기에는 너무 큽니다.)

## 5. 잘 보이는 곳과 안 나온 곳 (한계)

- **잘 보이는 방향: 정면과 오른쪽 옆·뒤.** 0~9번 장면이 서로 많이 겹치고 이웃 장면 사이 시차가 작아서(약 15°) 깊이가 촘촘하게 나왔습니다. 장면마다 남은 점이 7만~11만 개입니다.
- **왼쪽 뒤의 빈자리 → 정렬 실패.** 16~19번 4장은 정렬에 실패했습니다. 16번은 흔들려 흐렸고(선명도 39, 다른 장면은 대개 100 이상), 17~19번은 피규어가 화면 아래 끝에 반쯤 잘려 있어 짝을 찾을 부분이 적었습니다. 정렬되지 않은 장면은 복원에 쓰이지 않으므로, 이 방향에서 보면 알갱이가 듬성하고 검은 빈자리가 보입니다.
- **그 근처도 듬성함 → 시차가 끊김.** 빠진 4장 양옆인 14·15·20·21번은 이웃 장면이 한쪽밖에 없어서, 다른 장면과 깊이가 맞은 점이 7,859~18,347개뿐입니다.
- **머리카락·번개 이펙트 주변 잡티 → 시차로 깊이를 못 정함.** 가늘고 반투명한 부분은 장면마다 모양이 달라 보여서 깊이가 흔들렸고, 일부 알갱이가 흩어졌습니다.
- **바닥이 없음 → 잘못된 정렬을 막으려고 뺌.** 나무결 무늬가 반복돼서 다른 위치의 무늬끼리 짝이 맞춰지므로, 피규어만 오려 내서 복원했습니다.
- **개선 방법:** 왼쪽 뒤를 지날 때 더 천천히, 피규어가 화면 가운데 오도록 찍으면 그쪽도 정렬되어 빈자리가 줄어들 것입니다.
