# 피규어 3D 뷰어 (가우시안 스플랫)

폰으로 찍은 사진 9장으로 바닥 위의 피규어를 3D 알갱이(가우시안 스플랫)로 만들고, 웹에서 돌려 볼 수 있게 했습니다.

- 공개 주소: https://gsahn26.github.io/my-open-space/
- 장면 파일 직접 확인: https://gsahn26.github.io/my-open-space/scene.sog

## 1. 공개 판단

내 방 바닥에 놓은 피규어만 가까이 찍어서 사람 얼굴, 문패, 모니터 화면, 주소 같은 개인정보가 화면에 없으므로 공개해도 된다고 판단했습니다.

## 2. 촬영

| 항목 | 값 |
|---|---|
| 대상 | 나무 바닥 위 피규어 |
| 촬영 방식 | 동영상 대신 **사진 9장**, 피규어 둘레를 돌며 촬영 (약 36초 동안) |
| 경로 | 피규어 둘레를 한 바퀴 돌며 정면·옆·뒤에서 촬영 |
| 원본 해상도 | 4284 × 5712 (HEIC) → 복원용 900 × 1200으로 축소 |
| 사용 프레임 | 9장 중 **7장이 카메라 위치 추정에 성공** (뒤쪽 2장은 실패) |

## 3. 복원 방법

교안은 코랩 T4에서 MapAnything을 쓰지만, 이번에는 GPU 없이 CPU에서 아래 방법으로 만들었습니다.

1. DISK 특징점 + LightGlue 매칭 → COLMAP(SfM)으로 카메라 위치와 드문드문한 점 추정
2. 카메라 위치를 고정하고 매칭 점을 삼각측량 (7,260개)
3. 평면 스윕 스테레오로 사진마다 깊이를 구하고, **다른 사진 2장 이상과 깊이가 맞는 점만** 남김
4. 피규어 주변 범위로 자르고 튀는 점을 제거 → 106,724개

## 4. 측정값

| 항목 | 값 |
|---|---|
| 점(알갱이) 개수 | 106,724 |
| 카메라 퍼짐 비 | 1.45 (카메라 상자 대각선 10.0 ÷ 장면 상자 대각선 6.90) |
| 장면의 가장 긴 변 | 4.485 (SfM 단위, 실제 cm 아님) |
| 알갱이 반지름 | K = 0.8 → 0.01098 (K = 1.4는 너무 뭉개져서 줄임) |

퍼짐 비가 1보다 큰 것은 작은 피규어 둘레를 크게 돌며 찍었기 때문입니다. 추정된 카메라 위치가 피규어를 둘러싼 모양으로 나와 실제로 돈 방향과 맞는지 확인했습니다.

### 형식별 비교 (splat-transform 3.10.3)

| 형식 | 파일 크기 (바이트) | 변환 시간 | 알갱이 수 | 알갱이당 바이트 |
|---|---:|---:|---:|---:|
| 원본 `.ply` | 7,257,648 | – | 106,724 | 68.0 |
| `.compressed.ply` | 1,738,267 | 1.08초 | 106,724 | 16.3 |
| `.spz` | 909,590 | 1.04초 | 106,724 | 8.5 |
| **`.sog` (사용)** | **626,864** | 2.32초 | 106,724 | **5.9** |

세 형식 모두 알갱이 수는 같고, SOG가 원본보다 약 11.6배 작아서 웹에 올릴 파일로 골랐습니다. 뷰어 화면에 다른 형식 파일을 끌어다 놓으면 같은 시점에서 비교할 수 있습니다.

## 5. 잘 보이는 곳과 안 나온 곳 (한계)

- **잘 보이는 방향**: 정면과 왼쪽 앞. 사진 00, 02, 03, 04가 서로 많이 겹쳐서 깊이가 촘촘하게 나왔습니다.
- **구멍이 보이는 방향: 뒤쪽**. 뒤에서 찍은 사진 2장(07, 08)은 앞쪽 사진과 겹치는 부분이 너무 적어 카메라 위치를 못 구했습니다. 그래서 뒷면 알갱이가 거의 없고, 돌려 보면 뒤가 비어 배경이 보입니다. 사진 사이 각도가 40° 넘게 벌어져서 **시차가 이어지지 않은 것**이 원인입니다.
- **머리카락·번개 이펙트 주변 잡티**: 가늘고 반투명한 부분은 사진끼리 같은 점을 찾기 어려워 알갱이가 흩어졌습니다.
- **바닥 앞쪽 얼룩**: 나무결 무늬가 반복돼서 깊이를 잘못 맞춘 점이 일부 남았습니다.
- 다음에는 동영상으로 천천히 한 바퀴 돌며 찍어서(프레임 24장 이상) 뒤쪽도 이어지게 하면 개선될 것입니다.
