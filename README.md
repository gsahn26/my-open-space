# 피규어 3D 뷰어 (가우시안 스플랫)

폰으로 찍은 사진 7장으로 바닥 위의 피규어를 3D 알갱이(가우시안 스플랫)로 만들고, 웹에서 돌려 볼 수 있게 했습니다.

- 공개 주소: https://gsahn26.github.io/my-open-space/
- 저장소 주소: https://github.com/gsahn26/my-open-space
- 장면 파일 직접 확인: https://gsahn26.github.io/my-open-space/scene.sog

## 1. 공개 판단

**내 방 바닥에 놓은 피규어만 가까이 찍었고, 사람 얼굴·문패·모니터 화면·주소 같은 개인정보가 화면에 없으므로 남에게 보내도 되는 공간이라고 판단했습니다.** 또 복원할 때 피규어만 오려 내서 배경(방 모습)은 결과 파일에 들어가지 않습니다.

## 2. 촬영

| 항목 | 값 |
|---|---|
| 대상 | 나무 바닥 위 피규어 |
| 촬영 방식 | 동영상 대신 **사진 7장**, 피규어 둘레를 돌며 촬영 |
| 원본 해상도 | 3024 × 4032 (6장), 4284 × 5712 (1장), HEIC → 복원용 1200 × 1600으로 축소 |
| 사용 프레임 | 7장 중 **5장이 정렬(카메라 위치 추정)에 성공** (00, 01, 02, 05, 06). 뒤쪽 03, 04는 실패 |

## 3. 복원 방법

교안(room-3d 스킬)은 코랩 T4에서 MapAnything을 씁니다. 이번에는 코랩 계정 인증과 모델 내려받기를 할 수 없는 환경이라, GPU 없이 CPU에서 아래 방법으로 만들었습니다. 알갱이 만들기, 줄이기, 띄우기는 스킬과 같은 방법입니다.

1. 사진마다 피규어만 오려 내는 마스크를 만듦 (rembg). **나무 바닥 무늬가 엉뚱한 짝을 만들어서** 바닥은 뺐습니다.
2. 피규어 부분만 잘라 DISK 특징점 + LightGlue로 짝을 찾음 → COLMAP으로 카메라 위치 추정 (5장 정렬, 점 660개)
3. 정렬된 5장으로 평면 스윕 스테레오를 해서 사진마다 깊이를 구함 (NCC 0.6 이상만)
4. **다른 사진 2장 이상과 깊이가 1% 안으로 맞는 점만** 남김 → 61,213개
5. 각 축 0.5~99.5 백분위 밖, 이웃과 멀리 떨어진 점 제거 → **56,407개**
6. 점을 알갱이로 바꿈. 칸 17개(각도별 색 `f_rest` 없음), y·z 부호 뒤집기
7. `splat-transform@3.10.3`으로 `.sog`(SOG v2) 변환

## 4. 측정값

| 항목 | 값 |
|---|---|
| 알갱이 수 | 56,407 |
| 카메라 퍼짐 비 | 1.88 (카메라 상자 대각선 10.0 ÷ 장면 상자 대각선 5.307), 기준 0.1보다 큼 |
| 장면의 가장 긴 변 | 3.279 (SfM 단위, 실제 cm 아님) |
| 알갱이 반지름 | K = 1.4 → r = 1.4 × 3.279 ÷ √56,407 = 0.01933 |

퍼짐 비가 1보다 큰 것은 작은 피규어 둘레를 크게 돌며 찍었기 때문입니다. 추정된 카메라 5곳이 피규어를 둘러싼 모양(중심에서 거리 약 5~6)으로 나와, 실제로 돈 방향과 맞는 것을 확인했습니다.

### 형식별 비교 (splat-transform 3.10.3)

크기는 바이트 단위입니다. (1KB = 1,024바이트로 보면 `.sog`는 325KB)

| 형식 | 파일 크기 (바이트) | 변환 시간 | 알갱이 수 | 알갱이당 바이트 |
|---|---:|---:|---:|---:|
| 원본 `.ply` | 3,836,091 | – | 56,407 | 68.0 |
| `.compressed.ply` | 919,082 | 0.91초 | 56,407 | 16.3 |
| `.spz` | 474,345 | 0.73초 | 56,407 | 8.4 |
| **`.sog` (사용)** | **332,763** | 1.75초 | 56,407 | **5.9** |

알갱이당 바이트 = 파일 크기 ÷ 알갱이 수. 원본 `.ply`가 정확히 68바이트라 헤더가 맞게 만들어졌습니다. 네 형식 모두 알갱이 수가 같고, SOG가 원본보다 약 11.5배 작아서 웹에 올릴 파일로 골랐습니다.

## 5. 잘 보이는 곳과 안 나온 곳 (한계)

- **잘 보이는 방향: 정면.** 사진 00, 01, 06이 정면 근처에서 서로 많이 겹치고 사진 사이 시차가 적당해서, 팔·다리·얼굴 윤곽이 가장 촘촘하게 나왔습니다. (정면 사진에서 남은 점: 00 18,101개, 01 17,367개, 06 15,289개)
- **뒤쪽의 검은 빈자리 → 정렬 실패.** 뒤에서 찍은 03, 04는 이웃 사진과 짝이 4~49개뿐이라 카메라 위치를 못 구했습니다(정렬 실패). 정렬되지 않은 사진은 복원에 쓰이지 않으므로 뒷면 알갱이가 거의 없고, 돌려 보면 뒤가 비어 검은 배경이 보입니다. 7장으로 한 바퀴를 돌아 이웃 사진 사이가 약 50°씩 벌어졌고, **시차가 너무 커서 같은 점을 이어 찾지 못한 것**이 원인입니다.
- **옆면이 듬성듬성함 → 시차가 커서 깊이가 덜 맞음.** 05번 사진은 정렬은 됐지만 이웃 사진과 각도 차가 커서, 다른 사진과 깊이가 맞은 점이 2,453개뿐입니다. 그래서 오른쪽 옆에서 보면 구멍이 많습니다.
- **머리카락·번개 이펙트 주변 잡티 → 시차로 깊이를 못 정함.** 가늘고 반투명한 부분은 사진마다 모양이 달라 보여서 깊이가 앞뒤로 흔들렸고, 일부 알갱이가 흩어졌습니다.
- **바닥이 없음 → 잘못된 정렬을 막으려고 뺌.** 처음에는 나무결 무늬가 반복돼서, 앞모습과 뒷모습 사진의 바닥 무늬끼리 엉뚱하게 짝이 맞춰졌습니다. 이대로면 정렬이 틀어지므로 피규어만 오려 내서 복원했습니다.
- **개선 방법:** 동영상으로 천천히 걸어서 한 바퀴 돌며 찍어(사진 24장 이상, 이웃 사이 15° 이하) 시차가 끊기지 않게 하면, 뒤쪽까지 정렬되어 빈자리가 줄어들 것입니다.
